# Касса — система учёта для продуктовых магазинов (white-label)

Десктопная касса на ПК (Windows): продажи со сканером, склад, приход, инвентаризация, отчёты и
**фискальные чеки через фискальный модуль (ФМ) ОФД Узбекистана** с печатью чека и QR-кодом.
Работает без интернета — данные хранятся локально (SQLite), чеки досылаются в ОФД автоматически.

## Что внутри
| Раздел | Возможности |
|---|---|
| **Касса** | сканер, весовой товар, горячие клавиши, нал/карта/смешанная, **насия (в долг)**, бонусы, отложенные чеки, экран покупателя |
| **Клиенты** | база по телефону, персональная скидка, кэшбэк бонусами, **долги с лимитом и погашением**, история и любимые товары |
| **Фискализация** | ФМ через FiscalDriveService, QR на чеке, автоповтор без дублей, Z-отчёты, чек возврата, насия = чек «кредит» |
| **Склад** | приход со средневзвешенной себестоимостью, **⚡ автозаказ** по скорости продаж, ревизия, списание, движение товара |
| **Ценники** | печать ценников и этикеток со штрихкодом EAN-13 / Code128, сразу после прихода — по количеству |
| **Деньги** | внесение, изъятие, расходы по категориям, сверка кассы при закрытии смены |
| **Отчёты** | выручка, прибыль, маржа, по дням/часам, топ, **ABC-анализ**, кассиры, неликвид, заканчивающиеся |
| **Контроль** | лимит скидки кассира, возврат и удаление строки по PIN админа, **журнал всех действий** |
| **Telegram** | ежедневный отчёт владельцу, закрытие смены с расхождением, крупные возвраты, ошибки ФМ, подбор PIN |

## Установка (один раз)
1. Установите Python 3.10+ (при установке отметьте **Add Python to PATH**) и Google Chrome.
2. Скопируйте папку `kassa` на ПК кассы, например в `C:\kassa`.
3. Запустите `install.bat`.
4. Установите драйвер чекового принтера (80 или 58 мм) и сделайте его **принтером по умолчанию**
   (в драйвере выставьте ширину бумаги и отключите поля).

## Запуск
`start_kassa.bat` — поднимает сервер и открывает кассу в отдельном окне Chrome.
Флаг `--kiosk-printing` печатает чек **сразу, без диалога**.
Вход: PIN **0000** (администратор) — смените его в «Настройки → Сотрудники».

Автозапуск при включении ПК: `Win+R` → `shell:startup` → положите туда ярлык `start_kassa.bat`.

## Подключение фискального модуля
1. Вставьте ФМ (USB-ключ / смарт-карту) в ПК.
2. Установите **FiscalDriveService** (выдаёт ОФД / ваш ЦТО) — он работает как служба Windows на
   `http://127.0.0.1:3449`.
3. В кассе: «Настройки → Фискальный модуль» → режим **«Фискальный модуль — FiscalDriveService»** →
   **«Найти ФМ»** → «Сохранить».
4. «Синхр. состояние» → если ФМ заблокирован (`Locked: true`), его разблокирует ОФД/ЦТО.
5. Откройте смену — в ФМ автоматически откроется Z-отчёт.

Режим **«Демо»** — встроенный эмулятор ФМ: можно обучать кассиров и показывать клиенту без железа.

### Что делается автоматически
- Каждый чек: TXID → регистрация в ФМ → ФП и QR печатаются на чеке.
- Сбой связи с ФМ: продажа не теряется, чек помечается «ожидает» и повторяется в фоне
  (по тому же TXID — дубликата не будет).
- Каждые N минут (настройка) неотправленные чеки и Z-отчёты уходят в ОФД.
  **Важно:** ФМ блокирует продажи, если чеки не отправлялись 2+ дня — держите интернет на кассе.
- Открытие/закрытие смены = открытие/закрытие Z-отчёта в ФМ.
- Возврат формирует фискальный чек возврата со ссылкой на исходный (RefundInfo).
- Резервная копия базы — при запуске и закрытии смены (`data/backups`, 30 дней).

### POS-ключ ЦТО (необязательно)
Привязывает ФМ к вашей кассе, чтобы чужое ПО не могло им пользоваться. «Сгенерировать» →
сохранить копию ключа → «Привязать ФМ». Отвязать можно только через ОФД — не теряйте ключ.

## Работа кассира
| Клавиша | Действие |
|---|---|
| скан / Enter | добавить товар (повторный скан +1) |
| `5*` затем скан | добавить сразу 5 шт |
| F1 | поиск по названию |
| ↑ ↓, + −, `*`, Del | выбрать строку, кол-во ±1, задать кол-во, удалить |
| F7 / F8 | скидка на строку / на чек (сумма или `10%`) |
| F2 / F3 / F4 | оплата наличными / картой / смешанная |
| Enter на пустом поле | быстрая оплата наличными |
| F9 | последний чек |
| Esc | очистить |

Неизвестный штрихкод → администратор сразу создаёт товар и он попадает в чек.

## Товары
- Импорт из Excel/CSV (выгрузка из 1С и т.п.). Колонки распознаются по названию:
  Наименование, Штрихкод, Артикул, Цена, Себестоимость, Остаток, Категория, ИКПУ, Код упаковки,
  Код единицы, НДС, Ед, Мин. остаток.
- **ИКПУ (MXIK) и код упаковки** берутся на tasnif.soliq.uz — без них ОФД может не принять чек.
  В списке товаров позиции без ИКПУ подсвечены.
- Товарам без заводского штрихкода — кнопка «Авто» (внутренний EAN-13 с префиксом 200).

## Брендирование под клиента
«Настройки → Магазин и чек»: название, ИНН, адрес, телефон, текст внизу чека, ширина ленты, цвет
интерфейса. Каждому клиенту — своя копия папки (`data/` создаётся при первом запуске).

## Файлы
```

db.py         схема базы, настройки, бэкапы
```

## Склад: статусы, история цен, возврат поставщику

**Статусы остатков** (Товары на кассе, «Остатки → Статусы» в Центре): Нет в наличии · Мало (не выше минимума) · Зона риска (закончится за 3 дня при текущих продажах) · Без продаж (30 дней) · Избыток (запас больше чем на 60 дней) · В наличии. В Центре — по каждому магазину, с фильтрами по магазину, категории, бренду и выгрузкой в Excel.

**История цен** — в карточке товара «📈 История цен»: кто, когда и откуда поменял цену или закупку (карточка, переоценка, уценка, Центр, импорт).

**Возврат поставщику** — Поставщики → «↩ Возврат поставщику»: причина, товары сканером, цена закупки. Остаток уменьшается, долг перед поставщиком — тоже; печатается акт для подписи. Видно в оборотной ведомости отдельной колонкой.

**Штрихкод «Авто»** — внутренний EAN-13 с префиксом 200 и правильной контрольной цифрой (в кассе и в Центре).

## Сотрудники и роли в Центре

Вход в Центр: **логин + пароль** сотрудника. Пустой логин + общий пароль `HQ_PASSWORD` — вход Super Admin (оставлен на случай, если все пароли забыты).

Роли: Super Admin, Владелец, Директор, Региональный менеджер, Управляющий магазином, Заведующий складом, Кассир, Аналитик.
Управляющий, кассир, склад и региональный видят **только свои магазины** — выручку, остатки, накладные, уведомления и журнал. Без права «Прибыль» скрыты себестоимость, прибыль и маржа. Таблица прав — «Сотрудники и доступ → Роли и права».

Магазины → карточка филиала: показатели дня и месяца, **план продаж** (на 3 месяца вперёд), прогноз выполнения и сколько нужно продавать в день, рентабельность, история 12 месяцев, сотрудники, история действий. Вкладка «Сравнение» — все филиалы за любой период с лучшими показателями.

## Обзор, аналитика, акции и цены

**Обзор** (первая вкладка у администратора) — выручка, чеки, средний чек и прибыль за сегодня со сравнением со вчера к этому же часу; график 14 дней и по часам; способы оплаты (нал / карта / QR / насия); состояние склада (нет в наличии, ниже минимума, минусы, просрочка); долги клиентов и поставщикам; топ товаров и последние чеки. Обновляется каждую минуту.

**Отчёты** — вкладки, любой отчёт за любой период, кнопка «⬇ Excel»:
- *Продажи* — сравнение с прошлым периодом той же длины, выручка по дням, тепловая карта «день недели × час» (для графика смен и завоза), оплаты, категории, акции.
- *Товары ABC/XYZ* — матрица ABC × XYZ с рекомендациями, сколько дней хватит остатка, «замороженные» деньги в товаре.
- *Оборотная ведомость* — остаток на начало, закупка, приёмка, возвраты, излишки, продажи, списания, отгрузки, недостачи, остаток на конец.
- *Прибыль и расходы* — выручка → себестоимость → валовая прибыль → расходы по статьям → списания и ревизии → чистая прибыль.
- *Сотрудники* — часы, чеки, выручка в час, скидки, возвраты, удалённые строки, очищенные чеки, расхождения кассы и уровень риска.
- *НДС* — продажи по ставкам и сумма НДС.

**Акции** (Ещё → Акции и цены) — скидка % или «2+1» на весь магазин, категории или товары; даты, часы («счастливые часы»), дни недели. Касса сама применяет лучшую акцию и показывает её в строке чека.

**Оптовые цены** — в карточке товара поле «Оптовая цена», у клиента «Тип цен: оптовые». Выбрали такого клиента на кассе — цены в чеке становятся оптовыми.

**Переоценка** (Товары → ↕ Переоценка) — отмеченные товары, категория или все: на %, наценка от закупки или одна цена; округление; предпросмотр с предупреждением «ниже закупки»; после применения — печать новых ценников. История — в «Акции и цены».

**QR-оплата** (кнопка «QR Click/Payme», Shift+F3) — отдельно учитывается в отчётах и Z-отчёте, в фискальный чек уходит как безналичная оплата (PaymentType 3).

## Новые функции — как пользоваться

**Клиенты и бонусы.** На кассе `F5` → телефон → клиент в чеке. Персональная скидка применяется сама,
бонусы (кэшбэк, % в «Настройки → Лояльность») начисляются с оплаченной части и списываются в окне оплаты.

**Насия (в долг).** `F6` → предоплата наличными (можно 0) → остаток записывается клиенту. Лимит долга —
в карточке клиента. Погашение: «Клиенты» → «Погасить» (наличные попадают в кассу смены).
В ФМ такой чек уходит с типом «кредит» (Type = 2) — уточните у вашего ЦТО, что это соответствует их требованиям.

**Отложенные чеки.** `F10` — отложить (клиент пошёл за другим размером), `F11` — вернуть.

**Экран покупателя.** Кнопка 🖥 в шапке → окно перетащите на второй монитор и разверните (F11).

**Весовой товар.** Весы печатают штрихкод `PP CCCCC WWWWW K` (PP — префикс 20–29, CCCCC — PLU, WWWWW — вес в граммах).
Укажите PLU в поле «Штрихкод» или «Артикул» товара — касса сама подставит вес.

**Ценники.** «Товары» → отметить галочками → 🏷 Ценники. После прихода касса предложит напечатать
этикетки на весь принятый товар.

**Автозаказ.** «Приход» → ⚡ Автозаказ: что и сколько заказать, исходя из продаж за 30 дней и запаса на N дней.
«Скопировать для поставщика» — готовая заявка для Telegram.

**Контроль кассиров.** Скидка выше лимита, возврат и (по желанию) удаление строки требуют PIN администратора.
Всё пишется в «Журнал»; важные события дублируются в Telegram.

**Telegram.** @BotFather → токен → напишите боту /start → «Найти chat_id» → «Сохранить» → «Отправить тестовый отчёт».
Компьютеру кассы нужен интернет.

## 1. Запустить Центр на Railway
1. Залейте папку `hq/` в отдельный GitHub-репозиторий (или укажите Root Directory = `hq`).
2. Railway → New Project → Deploy from GitHub.
3. Variables: `HQ_PASSWORD` = ваш пароль, `DATA_DIR` = `/data`.
4. Добавьте **Volume** с точкой монтирования `/data` (иначе база сотрётся при редеплое).
5. Settings → Networking → Generate Domain. Откройте адрес, войдите паролем.

Локально для проверки: `cd hq && pip install -r requirements.txt && python hq.py` → http://127.0.0.1:8080 (пароль `admin`).

## 2. Подключить магазины
1. Центр → **Магазины** → «+ Магазин» → «Скопировать токен».
2. Касса → **Настройки → Сеть магазинов** → адрес Центра + токен → «Подключить».
3. Каталог из Центра загрузится в кассу. Существующие товары с тем же штрихкодом склеятся, остатки не трогаются.
   Чтобы сразу видеть остатки в Центре, после подключения сделайте ревизию или введите начальные остатки.

## 3. Каталог
Товары и цены ведутся **в Центре** (Каталог → импорт Excel или вручную) и сами расходятся по кассам.
На кассе у таких товаров можно менять только «мин. остаток». Товар, созданный на кассе (неизвестный штрихкод),
автоматически уходит в общий каталог.

## 4. Приход по штрихкоду
**Поставка от поставщика:** Центр → Накладные → «+ Поставка в магазин» → сканируйте товары или загрузите Excel поставщика → «Отправить».
На кассе появится «Поступления (1)». Кладовщик открывает накладную и **сканирует каждую единицу**:
- зелёный ✓ — позиция сошлась, жёлтый — не хватает, красный — больше чем в накладной или лишний товар;
- большая карточка показывает последний отсканированный товар «принято / ожидается»;
- `10*` перед сканом — сразу 10 штук; количество можно поправить руками;
- «Провести» — показывает **акт расхождений** с комментарием, остаток увеличивается на факт, Центр видит недостачу/излишек.
После приёмки касса предлагает напечатать этикетки на принятый товар.

**Без Центра:** «Поступления» → «Накладная поставщика из Excel» (штрихкод, количество, цена) → та же сверка сканером.

## 5. Перемещения между магазинами
- **Из Центра:** Накладные → «⇄ Перемещение» (откуда → куда). Магазин-отправитель увидит «К отгрузке», сканирует товар в коробку и отгружает,
  получатель видит её у себя и принимает сканером. Расхождения в пути видны в Центре.
- **Из магазина:** Поступления → «Отправить в другой магазин» → сканировать → «Отгрузить».

## 6. Что видит владелец в Центре
- **Обзор:** выручка, чеки, прибыль сети и каждого магазина в реальном времени, кто онлайн, тренд 14 дней, топ-10, расхождения при приёмке.
- **Остатки:** матрица товар × магазин, красным — ниже минимума (видно, откуда перебросить).
- **Продажи:** по магазинам и топ-50 товаров за период.

# 🚚 Переезд из другой программы
Центр → **Переезд**. Порядок: **1. Товары → 2. Остатки → 3. Клиенты → 4. История продаж**.
1. Выгрузите отчёт из старой программы в Excel (.xlsx) или CSV (подходит и кодировка Windows-1251 из 1С).
2. «Загрузить файл» → система сама найдёт строку заголовков (шапку отчёта пропустит) и сопоставит колонки — проверьте.
3. **«Проверить»** — ничего не записывается, видно сколько загрузится, сколько пропустится и почему
   (магазин не найден, товара нет в каталоге, нет цены). Строки «Итого» пропускаются сами.
4. **«Загрузить»**. Остатки, клиенты и история доходят до касс за минуту; статус — в таблице «Загруженные данные».

Подсказки:
- Магазины сопоставляются по названию, в том числе кириллица ↔ латиница («Атлас Чимган» = «Atlas Chimgan»).
  Неизвестные склады можно пропустить или создать как новые магазины.
- Остатки: режим «Заменить» (на дату переезда) или «Прибавить».
- Клиенты: бонусы и долги переносятся в кассу магазина клиента, повторная загрузка не задваивает долг.
- История продаж нужна, чтобы автозаказ и неликвид работали с первого дня.
- Магазин без Центра: Клиенты → «Импорт из Excel»; товары и остатки — Товары → «Импорт».
- Примеры файлов — папка `primery_vygruzok/`.


# 🥖 Продуктовый магазин

**Быстрые кнопки** (F12 — показать/скрыть). Товары без штрихкода: хлеб, лепёшка, овощи, фрукты, развес.
Включаются в карточке товара: «Быстрая кнопка на кассе». Весовой товар (ед. «кг», «г», «л») открывает ввод веса
с кнопками 0.25 / 0.5 / 1 / 1.5 / 2 / 3. Штрихкоды с весов (префикс 20–29) по-прежнему распознаются сами.

**Упаковки.** Карточка товара → «Штрихкоды упаковок…»: блок сигарет ×10, упаковка воды ×6, ящик ×12.
Скан штрихкода упаковки добавляет сразу нужное количество штук.

**Маркировка Asl Belgisi.** В карточке товара «Маркировка — Да». На кассе такой товар добавляется только сканом
кода DataMatrix (квадратный код на пачке/бутылке): если отсканировать обычный штрихкод, касса попросит марку.
Один код нельзя пробить дважды; после возврата код снова доступен для продажи. Коды уходят в фискальный чек (поле Labels).
Нужен 2D-сканер. Перечень маркируемых групп расширяется поэтапно — уточняйте актуальный список на aslbelgisi.uz.

**18+ и алкоголь.** «Ограничение: 18+» — касса спросит кассира, проверен ли возраст (один раз на чек, пишется в журнал).
«Алкоголь» — плюс запрет продажи вне часов из «Настройки → Продукты» (поставьте часы по требованиям вашего хокимията).

**Сроки годности.** «Годен до» вводится при приходе и при приёмке накладной; если не указано — берётся
«Срок годности, дней» из карточки товара. Раздел «Сроки»: что просрочено и что истекает, потери в деньгах,
«Уценить» (−20/30/50% + печать ценника) и «Списать». Остаток раскладывается по партиям автоматически (старое продаётся первым).
Просрочка попадает в ежедневный отчёт в Telegram.

**Поставщики и долги.** В приходе укажите поставщика и сколько оплачено сейчас (пусто — всё в долг), способ и срок оплаты.
«Ещё → Поставщики»: наш долг каждому, история, «Оплатить» (наличные из кассы уменьшают кассу смены).
Общий долг поставщикам — в Telegram-отчёте.


# ⬆ Автообновление

Весь код — в репозитории `asadbekfxadd/kassa-hq`: касса в корне, Центр в папке `hq/`.
Push в `main` → Railway пересобирает Центр → Центр раздаёт новую версию кассы.

- Касса проверяет обновления раз в 30 минут (нужно подключение к Центру: «Настройки → Сеть магазинов»).
- Скачанное обновление ставится само **при закрытии смены** или **при следующем запуске**.
  Администратор может нажать жёлтую кнопку «⬆ Обновление» в шапке — касса перезапустится за ~10 секунд.
- Папка `data\` (база, настройки, резервные копии) не затрагивается никогда.
- Версия каждой кассы видна в Центре → Магазины.
- Запускайте кассу только через `start_kassa.bat`: он перезапускает сервер после обновления и доустанавливает зависимости.
