# Нагрузочный тест Центра

**Данные:** 100 магазинов, 5 000 товаров, 300 000 строк остатков, 540 000 чеков за 90 дней (1,62 млн позиций),
50 000 клиентов, 300 сотрудников. PostgreSQL 16 и Центр на одной машине, без прогретого кэша ОС.
Генератор: `load_gen.py`, замер: `load_bench.py` — по 3 запроса на экран, в таблице медиана.

| Экран / операция | До оптимизации | После |
|---|---:|---:|
| Обзор сети — день | 2,3 с (тревоги — минуты) | 1,2 с |
| Обзор сети — месяц | 2,9 с | 2,0 с |
| Тревоги | > 60 с | 1,6 с |
| Каталог (поиск) | 2,6 с | 0,02 с |
| Остатки: статусы магазина | 0,1 с | 0,1 с |
| Рекомендации перемещений | 6,3 с | 3 с первый раз, далее 0,03 с |
| Аналитика продаж — месяц | 2,0 с | 1,0 с |
| Аналитика продаж — 90 дней | 14,7 с | 2,4 с |
| ABC/XYZ — 90 дней | 7,5 с | 6,6 с |
| Сезонность (24 месяца) | 3,9 с | 2,3 с |
| Прибыль и убытки, денежный поток | 0,2 с | 0,2 с |
| Персонал + KPI | 0,3 с | 0,1 с |
| Клиенты (50 000, сегменты, LTV) | 1,1 с | 1,0 с |
| AI-помощник: сводка | 13,8 с | 4,2 с |
| Синхронизация кассы: 300 чеков | 0,2 с | 0,3 с |
| Синхронизация: пустой обмен (раз в минуту) | 0,01 с | 0,01 с |

100 касс, которые обмениваются раз в минуту, дают меньше 2 запросов в секунду, по 10–300 мс каждый. Это несколько процентов одного ядра.

## Что сделано

- **Индексы**: `sales(created_at)`, `sale_items(product_uid)`, `stock(product_uid)`. Каталог считал остаток каждого товара полным перебором — теперь это 16 мс.
- **Итоги чека в `sales`** (`cost_total`, `items_n`, `units`). Их записывает синхронизация, старые чеки досчитываются один раз при запуске.
  Выручку, прибыль, магазины, дни и карту часов отчёты теперь берут из чеков, без соединения с позициями.
  Позиции нужны только при фильтре по категории или бренду.
- **Тревоги и «товары без продаж»**: вместо подзапроса на каждую строку остатков (300 000 подзапросов) — одна выборка и сравнение в памяти.
- **Общий кэш продаж и остатков «магазин × товар»** (`hq/salescache.py`). Тревоги, обзор, статусы остатков, рекомендации и AI-помощник
  считают его один раз. Новые чеки и остатки с касс попадают в кэш сразу, полный пересчёт — раз в 2 минуты в фоне.
- **Аналитика**: категории с брендами и товары с недельными рядами XYZ считаются за один проход по позициям вместо двух-трёх.
- **Рекомендации перемещений** запоминаются на минуту и пересчитываются сразу, если изменились документы, продажи или остатки.

## Ограничения

- ABC/XYZ за 90 дней по всей сети — самый тяжёлый отчёт (около 6–7 с). Он разбирает каждый товар по дням. За месяц или по одному магазину он в 3–5 раз быстрее.
- Первый запрос после запуска сервера строит кэш продаж (около 3 с). Дальше кэш держит фоновый поток.
- Замер сделан на синтетических данных, где каждый чек — 3 случайных товара из 3 000. В реальном продуктовом магазине покупки повторяются
  (хлеб, молоко, вода), поэтому группировки сжимаются сильнее, и отчёты будут не медленнее приведённых.
