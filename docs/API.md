# API Центра сети

Полный список методов с правами доступа строится из кода и всегда актуален:
**`/api-docs`** (страница после входа в Центр) и **`/api/reference`** (JSON).
Ниже — общие правила и протокол синхронизации касс, который со страницы не виден целиком.

## Общие правила

- Формат — JSON в UTF-8. Даты — строки `ГГГГ-ММ-ДД ЧЧ:ММ:СС` по времени Ташкента. Суммы — в сумах.
- Ошибка — HTTP 400/401/403/404/429 и тело `{"error": "текст для человека"}`.
- Вход: `POST /api/login {"login": "...", "password": "..."}` → cookie сессии (30 дней, HttpOnly, Secure на сервере).
  5 неверных попыток за 15 минут с одного адреса или на один логин → `429` на 15 минут.
- Права проверяются на сервере по роли (8 ролей ТЗ) и списку магазинов пользователя; интерфейс только прячет кнопки.
  Себестоимость и прибыль отдаются как `null` без права «Прибыль, себестоимость».
- Важные действия пишутся в журнал (`GET /api/audit`).

## Синхронизация кассы: `POST /sync`

Касса шлёт запрос раз в минуту (и сразу после продажи, если есть связь). Заголовок `X-Store-Token: <токен магазина>`.
Обмен **идемпотентный**: всё, что имеет `uid`, повторно не создаётся; касса отмечает отправленным только то, что Центр подтвердил в `acks`.

### Вверх (касса → Центр)

| Поле | Что | Ключ |
|---|---|---|
| `sales[]` | чеки продаж и возвратов с позициями, оплатами (нал/карта/QR/долг), кассиром (`cashier_uid`), клиентом (`customer_uid`), статусом ФМ | `uid` |
| `money[]` | кассовые операции (расход, внесение, изъятие, погашение долга) и оплаты/возвраты поставщикам | `uid` |
| `stock[]` | остатки товаров, изменившиеся с прошлого обмена | `uid` товара |
| `docs[]` | принятые поставки, отгруженные/собираемые перемещения | `uid` документа |
| `new_products[]` | товары, созданные на кассе | `uid`, склейка по штрихкоду |
| `users[]` | сотрудники кассы (для «Персонала» и KPI) | `uid` |
| `customers[]` | клиенты, у которых изменились контакты, бонусы или долг | `uid`, склейка по телефону / карте |
| `info` | версия кассы, смена, наличные в кассе, долги, стоимость остатков, ошибки сотрудников | — |
| `since`, `cust_since` | курсоры каталога и базы клиентов | — |

### Вниз (Центр → касса)

| Поле | Что |
|---|---|
| `acks` | `{sales, money, docs, products, customers}` — что принято; `products` — `{uid, hq_uid}` при склейке по штрихкоду |
| `products[]` | изменения каталога и цен с `since` |
| `docs[]` | накладные к приёмке и задания на отгрузку для этого магазина |
| `cancelled[]` | `uid` документов, отменённых в Центре |
| `employees[]` | сотрудники магазина, управляемые Центром: имя, ПИН, роль, активен ли |
| `customers_net[]`, `cust_time` | единая база клиентов сети с уровнем, скидкой и кешбэком уровня; новый курсор |
| `pending` | данные переезда (остатки, клиенты, история продаж) — касса подтверждает через `POST /sync/ack` |
| `server_time`, `store`, `stores[]` | время сервера (новый `since`), этот магазин и другие магазины сети |

### Гарантии против двойных проводок

- Продажа, операция с деньгами, документ, клиент принимаются один раз по `uid` (повторная отправка → только `ack`).
- Документ перемещения меняет статус только вперёд (`to_ship → preparing → sent → received → completed`); повтор старого статуса игнорируется.
- Касса снимает отметку «отправить» с документа только если он не изменился, пока шёл обмен.
- Остаток на кассе меняется только через журнал движений (`stock_moves`) — триггеры не дают изменить его в обход.

## Обновление кассы

`GET /update/version` → `{version, sha256, files, notes}`; `GET /update/kassa.zip` — архив (оба с `X-Store-Token`).
Касса проверяет раз в 30 минут, скачивает и ставит обновление при запуске, при закрытии смены или по кнопке «⬆ Обновление». Папка `data/` не трогается.

## Ленты для Google Sheets

`GET /feed/<ключ>/<sales_daily|stock|products|plans>.csv` — CSV без входа, по секретному ключу из «Интеграции → Google Sheets».
Ключ перевыпускается там же — старые ссылки перестают работать. Себестоимость в ленты не попадает.
