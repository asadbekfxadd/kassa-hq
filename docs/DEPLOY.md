# Запуск и сопровождение

## Центр сети (Railway)

1. Сервис из GitHub-репозитория; сборка — `railway.json` (Railpack), запуск — `python hq/hq.py`, проверка — `/health`.
   Каждый push в `main` автоматически пересобирает Центр, а кассы получают новую версию сами.
2. База — PostgreSQL на Railway (переменная `DATABASE_URL`). Без неё Центр работает на SQLite в `DATA_DIR` (только для проверки).
3. Переменные окружения:

| Переменная | Зачем | Обязательна |
|---|---|---|
| `DATABASE_URL` | PostgreSQL | да |
| `HQ_PASSWORD` | общий пароль владельца (вход с пустым логином) — длинный и уникальный | да |
| `SECRET_KEY` | подпись cookie сессий; при смене все выйдут из системы | да |
| `TZ`, `APP_TZ` | `Asia/Tashkent` | да |
| `DATA_DIR` | рабочая папка (временные файлы) | нет |
| `INTEGRATIONS_WORKER` | `0` — отключить фоновые отправки (только для отладки) | нет |

4. После первого входа по `HQ_PASSWORD` создайте себе личную учётку «Владелец» в «Доступ в Центр» и входите через неё.

## Касса магазина (Windows)

1. Python 3.10+ («Add to PATH»). Распаковать архив кассы, например в `C:\kassa`, один раз запустить `install.bat`.
2. Запускать `start_kassa.bat` (ярлык в автозагрузку). Касса открывается в Chrome / Edge в режиме приложения и работает на `127.0.0.1` —
   из сети магазина к ней не подключиться.
3. Первый вход — ПИН `0000`, сразу поменять в Настройки → Сотрудники.
4. Настройки → Сеть магазинов: адрес Центра и токен магазина (Центр → Магазины → карточка → «Токен кассы»).
5. Фискальный модуль: FiscalDriveService на этом же компьютере (порт 3449), принтер чеков — по умолчанию в Windows.

## Резервные копии

- **Центр**: каждый день в 03:00 копия всей базы (zip: таблицы в JSON Lines + manifest), 14 последних хранятся в самой базе
  (таблица `hq_backups`, переживают пересборку сервера). Скачать или сделать сейчас — «Система → Резервные копии».
  При подключённом Telegram каждая копия уходит и в чат — это копия вне сервера. Рекомендуется также включить
  резервное копирование самого PostgreSQL в настройках Railway.
- **Касса**: копия базы при запуске и при закрытии смены, 30 дней, папка `data\backups`. Перенос на другой компьютер — скопировать папку `data`.

### Восстановление Центра из копии

```bash
# на сервере (Railway → сервис → Shell) или локально с DATABASE_URL нужной базы
python hq/backup.py restore hq-backup-20261103-030000.zip          # в пустую базу
python hq/backup.py restore hq-backup-20261103-030000.zip --force  # с заменой текущих данных
```

Копия переносима между PostgreSQL и SQLite. После восстановления перезапустите сервис. Кассы продолжат обмен сами:
то, что они уже отправили, повторно не задвоится (обмен по `uid`).

## Безопасность — чек-лист

- [ ] `HQ_PASSWORD` и `SECRET_KEY` заданы, не `admin`; у каждого сотрудника Центра — личный логин и роль с минимальными правами.
- [ ] Управляющим назначены только их магазины.
- [ ] ПИН администратора кассы `0000` заменён; кассирам выданы свои ПИН (лучше — из Центра, «Персонал»).
- [ ] Telegram подключён: тревоги «касса без связи», отчёт дня, копии базы.
- [ ] Ссылки Google Sheets не публикуются; при утечке — «Новый ключ ссылок».
- [ ] Токен кассы при утечке — «Выпустить новый» в карточке магазина.

Что уже защищено в системе: пауза после 5 неверных паролей в Центре и 5 неверных ПИН на кассе; cookie только по HTTPS и недоступны скриптам;
запрет встраивания страниц во фреймы и заголовки безопасности; проверка прав на сервере для каждого запроса; ключи интеграций не показываются
после сохранения; все важные действия — в журнале.
